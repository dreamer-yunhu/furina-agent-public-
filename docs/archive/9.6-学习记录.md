## 〇、起始表象：agent 冒烟测试一片空白

`graph.py` 命令行冒烟：输入"联网搜索xxx" → 控制台无任何输出、立刻弹回 `User:` 提示。
排掉 `.env`、网络、博查 key 全没问题之后，锁定了三个**真根因**（bug 是静默的，所以"不知道哪里出问题"）：

1. **langgraph 流式事件类型是 `"messages"`（复数）不是 `"message"`** → `if event["type"]=="message"` 把所有 token 全过滤掉。
2. **`model.bind_tools(tools)` 返回值被丢弃** → 模型从没见过工具 → 永不产生 `tool_calls` → 工具节点是死路。
3. **节点没有 system prompt** → 模型自我介绍漂移成"我是 Claude"（链路没坏，是身份没钉）。

## 一、踩坑清单（每条都对应一个心智模型）

### 1. LangChain 层：model 是不可变对象
- `bind_tools()` **不改原对象，返回绑好工具的新对象**。丢弃返回值 = 什么都没发生。
- 铁证：`model.tools is None`。
- 源码路径：`langchain_openai/chat_models/base.py:2389` bind_tools → `:2495` `return super().bind(tools=...)`；tools 会被 `convert_to_openai_tool` 序列化成 OpenAI JSON-Schema dict。`bind` 在 `langchain_core/runnables/base.py:1851`，返回 **RunnableBinding 包装器**（持有原 model + 合并的 kwargs），原 model 纹丝不动。
- **落点**：绑定要发生在"既知道 model 又知道工具清单"的组装层；绑定后的外壳要传给节点用。

### 2. LangGraph 层
- `astream(stream_mode="messages")` 事件结构：`{'type': 'messages', 'data': (AIMessageChunk, metadata)}` —— 注意复数。
- `chunk.content` 为空的 chunk = 模型在**调工具**（内容在 `tool_calls` 里），别当文本吐。
- **checkpointer 挂 `compile(checkpointer=saver)`，不挂任何节点**。节点函数只认 state，无感；引擎在"节点跑前读快照、节点跑后写快照"。
- graph 编译时机：既然 compile 需要 saver，而 saver 在 lifespan 才建 → **把模块级 compile 改成 `build_graph(saver)` 工厂**，import 模块零副作用。

### 3. Windows + psycopg：三连坑（环境级）
1. `ImportError: no pq wrapper available` → psycopg3 是壳，需要底层 pq 实现：`uv add "psycopg[binary]"`（Windows 没有系统 libpq，binary 最省事）。
2. **`AsyncPostgresSaver` 不在顶层导出**，在 `.aio` 子模块：`from langgraph.checkpoint.postgres.aio import AsyncPostgresSaver`（顶层只有同步 PostgresSaver）。
3. **psycopg async 不兼容 Windows 默认 ProactorEventLoop** → 进程启动前 `asyncio.set_event_loop_policy(asyncio.WindowsSelectorEventLoopPolicy())`。**部署到 Linux（Y7000）没有此坑**，它是纯 Windows 开发机问题。

### 4. 连接池/生命周期层
- `from_conn_string` 内部悄悄替你设了 3 个参数（`aio.py:81-82`）：`autocommit=True / prepare_threshold=0 / row_factory=dict_row`。**手动建 `AsyncConnectionPool` 必须自己补 `kwargs`** ——尤其 `autocommit`：不设 → langgraph 写 checkpoint 从不显式 commit → **状态恢复不了且不报错**（最阴的坑）。
- `from_conn_string` 是 **context manager**（`async with` 退出即关池）→ 只适合一次性脚本。进程常驻要**手动**：`AsyncConnectionPool(open=False)` → `await pool.open()` → `AsyncPostgresSaver(pool)` → `setup()` → 挂 `app.state`；关闭时 `pool.close()`（**关池，不是关 saver**——saver 没有 `.close()`）。
- 资源三态 → FastAPI 三挂法：
  - **进程级**（engine / saver / graph）→ lifespan 建、`app.state` 挂、进程退才关
  - **请求级**（数据库 session）→ 依赖注入，从池借连接用完还
  - **会话级**（thread_id）→ 不是对象，是数据键
- 类比心法：**saver 该住进你家 `db_engine` 的位置**（`init_db` 建一次），不是路由里每请求 `async with`。

### 5. FastAPI 层
- **Pydantic body 参数名 ≠ body 字段名**：参数类型是 Pydantic model → 吃整个请求体；body 里的字段要用 `参数名.字段` 取。经典 bug：`rename_conv(new_title: RenameConversation, ..., title=new_title)` —— 传了整个对象，应该 `new_title.title`。
- **不可信输入要在门口校验**：HTTP path/body 是外部输入，别让 `uuid.UUID(str)` 裸抛 → 500。声明 `thread_id: uuid.UUID`（FastAPI 422）或 try→4xx。而 **token 里 str→uuid 转回安全**，因为那是后端自己签发+验签的（可信）。心法：**校验在不可信边界做一次；转回发生在可信内部**。
- **命令行 REPL（input/while/asyncio.run）和 HTTP 请求是两个世界**，别缝进一个端点（`asyncio.run` 在 async 端点里直接崩）。

## 二、学到的架构知识（心智模型）

### A. 工厂函数 / 闭包注入
`make_furina_node(llm)` = 高阶函数：把 `llm` 焊进内部 async 节点的**闭包**，返回函数对象。LangGraph `add_node` 存这个对象，运行时持有它、到期 `fn(state)` 才执行函数体。
- 关键：**`def` 只造对象不跑函数体**；闭包靠 `__closure__` cell 让 `llm` 逃过外层栈帧销毁。
- 自查：`node.__closure__[0].cell_contents` 能看到捕获的 llm。
- 框架回调签名把依赖注入逼到闭包里 → 用 `partial` 或工厂，而不是给节点硬加自定义参数。

### B. system prompt = agent 的第一道纪律
四要素：**身份钉死 / 工具纪律 / 工具黑名单 / 风格**。一份 system 同时治好"角色漂移 + 闲聊乱调工具"。接 PLAN 的人设注入/意图路由正门。

### C. checkpointer 的定位（三层）
业务节点（只管 state）｜框架引擎（自动 put/get）｜存储（checkpoints 快照）。
- **checkpoints 存"图状态快照 blob"，不是消息行**；`message` 表存给人看的展示记录。分工不同。

### D. 双存储体系决策（今天定的架构）
- `stream_chat`（老）：conversation + message 表，各自运转。
- `agent`（新）：**壳表**（AgentThreadID：钥匙 + user_id 归属）+ **checkpoints**（真正对话状态）。消息不进 message 表。
- `thread_id` 有两个"家"：运行态键在 checkpoints；业务归属凭证在壳表。缺了壳表 = 会话无主（无鉴权、无列表、无续聊入口）。

### E. id 契约
id 原生 `uuid.UUID`（DB/ORM）；出 API = `str`；进 LangGraph config = `str`；回 DB 查壳 = `uuid.UUID(...)`。**同一个 id，langgraph 吃 str、SQLAlchemy 吃 UUID**，两头都是同一个 `str(uuid4())` 就不会错位。
