## 〇、今日主线：孤儿数据 bug（9.6 遗留清单第 2 项）

**表象**：删 agent 会话只删了壳表，checkpointer 快照永久滞留。

**根因两处**（代码实锤）：
1. `init_pg_saver` 建了 `saver` 却只挂 `app.state.pool/graph`，**没挂 `app.state.saver`** → 删除路径手里没有 saver，想清都没工具。
2. `AgentThreadID` 表与 langgraph 的 `checkpoints/checkpoint_blobs/checkpoint_writes` 无任何外键 → cascade 摸不到快照。

**修复（验收通过）**：挂 saver + `get_saver` 依赖注入三层透传（router→service→repo），repo 的 `delete_thread` 内编排顺序：**先 `saver.adelete_thread(str(thread_id))` 清 checkpoint，再删壳 commit**。

**心智模型收获**（比 bug 本身值钱）：

### 1. 双存储删除：顺序即失败窗口
业务 `AsyncSession` 与 saver 的 autocommit 连接池是**两个独立事务域**，做不到原子 → 顺序决定中断时留什么孤儿：
| 顺序 | 中断后 | 可自愈性 |
|---|---|---|
| 先删壳 → 清 checkpoint | checkpoint 成孤儿，壳没了 | **不可自愈**（业务无入口） |
| 先清 checkpoint → 删壳 | 壳残留 | 可自愈（用户可重删，`adelete_thread` 幂等兜底） |

> 9.6 记录里那句"先 `saver.adelete_thread` 清快照、再删壳"是对的，今天从源码层面论证了为什么。

### 2. saver 是进程级对象，只能走依赖注入
`get_saver(request) -> request.app.state.saver` 抄 `get_graph` 范式；repository 拿不到 app.state，必须由 service 把 saver 参数透传进来。repo 签名 `delete_thread(session, *, thread_id, saver)`。

## 一、挖到的数据结构（源码驱动，别再当无头苍蝇）

### 3. `stream_mode="messages"` 有两个"V2"，别混
- **信封层 V2**：`astream(..., version="v2")` → 事件是 StreamPart 统一信封 `{type, ns, data}`（`types.py:264-352`）。**不改 data 内容**。
- **消息内容层 V2**：`configurable` 里设 `__pregel_stream_messages_v2=True` → `data[0]` 从 `AIMessageChunk` 换成 MessagesData dict（content-block 协议）。
- 切换条件在 `main.py:3241`：`version=="v2" AND config[CONF].get(CONFIG_KEY_STREAM_MESSAGES_V2)`。**只开 version=v2 时跑的还是 v1 handler → data[0] 仍是 AIMessageChunk**。
- v1 handler 会把 `ToolMessage`（工具结果）也 emit 出来 → **工具输出会混进文本流**（v2 才过滤，见 `_messages.py:307-314` 注释）。

**速查源码路径**（venv langgraph 1.2.11）：
- 消息流实现：`pregel/_messages.py`（StreamMessagesHandler / V2，emit 出口在 :104/:408）
- task metadata 五件套：`pregel/_algo.py:654-660`（`langgraph_step/node/triggers/path/checkpoint_ns`）
- 协议事件 TypedDict（v2 内容层）：`langchain_protocol/protocol.py`（MessageStartData / ContentBlockStart/Delta/FinishData / MessageFinishData…）

### 4. 强类型边界心法（今天最该带走的原则）
- **可信边界外**（HTTP path/query/body）：用强类型声明（`uuid.UUID`、`Query(ge=...)`），让框架进门时 422 → 函数体拿到的已经是合法对象，不再手写 `uuid.UUID(...)` 裸抛。
- **可信来源**（DB 读出 / 自己签发验签）：才允许内部转换。
- **格式校验在边界（Pydantic/类型声明），语义校验在业务层（404 归属）**——别指望 `uuid.UUID` 帮你鉴权。
- 反面教材（自己踩的）：`AgentRequest.chat_thread_id: str` + 函数体 `uuid.UUID()` → 校验被推迟到运行时，失败变 500 而非 422。且同接口族里 DELETE path 是强类型、POST body 是裸 str → 不对称。
- 防的不是"你的正常前端"（round-trip 值必合法），是"不受控的调用方"——curl、爬虫、前端脏数据。值合法 ≠ 契约健壮。

### 5. JWT + SSE 流式：走 fetch，不走 EventSource
- `EventSource` 不能自定义 header → `Authorization: Bearer` 送不出去。
- 走 `fetch + ReadableStream` 手拆 SSE 帧：换来 POST 语义、可带 header、可 `AbortController` 取消；代价只有一个坑——**帧会跨 TCP 包**，必须 buffer 累积 + `split("\n\n")` 留余量，`TextDecoder(stream:true)`。
- 你当前 CORS `allow_origins=* + allow_credentials=False` → cookie 路线焊死；fetch + Bearer 零改动复用 `get_current_user`。

## 二、业界方案沉淀（评审/讨论）

### 6. 流事件契约：主流三条铁律
1. `type` 判别的**封闭事件集**（前端 `switch(type)`），别用 `status` 魔法字符串表达"模型阶段"。
2. **错误是事件不是断流**：任何失败都以终态 `error` 事件送达（前端靠 done/error 区分结束与出错）。
3. 终态恰一次、幂等。

三流派可抄：Anthropic content block（text/tool_use/thinking 独立、`index` 标并行）· OpenAI Responses（文本/函数参数/reasoning/usage/completed/error 各一等事件）· LangGraph 自家（多通道并行 + `error` 是协议层 TypedDict 一等公民）。

对 ReAct 图最小事件集：`text_delta / tool_start / tool_end / done(带usage) / error`，子代理事件带 `agent` 归属。

### 7. 图错误捕获：官方三层 + 两种错误观
- LangGraph 1.x fault-tolerance 三机制顺序固定：node 异常 → **Retries**（默认不重试 ValueError/TypeError 等编程错误，只重试网络 5xx / NodeTimeoutError）→ **Error handling**（恢复函数）；`timeout=` 设 run/idle 上限；`set_node_defaults` 一次全图配。[参考 docs.langchain.com fault-tolerance]
- 分清两种错误：**工具业务失败 → 作为结果喂回 LLM 自愈**（不是图故障）；**基础设施故障 → 才走 retry/timeout**。
- 流边界兜错分两段：**启动前**错误直接 raise（响应未发出，还能回非 200）；**流中**错误 catch → yield `error` 终态事件（SSE 已发 200 改不回状态码）。

### 8. 多智能体演进：supervisor（已入 PLAN 十二）
- 目标：主管 = 监工 + 分配 + 唯一与用户交互；子代理独立执行汇报。
- 选型 **A 路线（子代理 = 工具）** 优先：上下文隔离 + 加组件 = 加一个工具；有"主管要看子代理内部/打断"需求再局部切 B（子图）。
- **异步 supervisor（丢后台）是 v2**；v1 用同步 + 流式进度——**慢 ≠ 必须异步**，用户看着进度不算干等。

## 五、午后讨论①：agent 人工干预（HITL）——"想加确认框"挖到"官方已内置"

> 一句话：从"给我的 agent 加入人工干预"的诉求出发，先铺开 HITL 主流方案地图，再翻 venv 源码发现 **langchain 1.3.18 已内置 `HumanInTheLoopMiddleware`**，最后用离线实验钉死了 supervisor 嵌套下 interrupt 是否冒泡的机制真相。结论：gate 不用手搓单图版，但嵌套结构决定要不要迁 `create_agent` 要自己想清楚。

### 5.1 主流方案三轴分类法（先建立坐标系再选型）

| 轴 | 分类 | 说明 |
|---|---|---|
| **介入时机** | 事前审批 / 事中接管 / 事后审查 | agent 动作敏感度决定；我的诉求天然偏事前（敏感工具审批） |
| **实现流派** | 静态断点 / **动态断点** / 人即工具 / 产出审查 | 静态=`interrupt_before/after` 编译期钉死，无差别拦截；动态=`interrupt()` 运行时按需，工具自声明敏感；人即工具=`ask_human` 模型自愿求助 |
| **状态传输** | 同步阻断 / 异步恢复 | interrupt 后 run 挂起到 checkpoint、放 HTTP 连接，人隔时经 `Command(resume)` 唤醒——**checkpointer 是异步恢复的地基** |

业界收敛共识：交互式 agent ≈ **动态 interrupt + 人作 gate + 状态外置**。

### 5.2 官方 HumanInTheLoopMiddleware = 你要的 gate（源码驱动）

**源码路径**：`langchain/agents/middleware/human_in_the_loop.py`（不是老版的 `langgraph/prebuilt/interrupt.py`——那文件只留 deprecated 的 TypedDict 壳）。

`HumanInTheLoopMiddleware.after_model`（:405）干的就是我原本想手搓的拦截层：
1. 扫最近 AI 消息的 `tool_calls`（reversed 找最后一条 AIMessage）
2. 命中 `interrupt_on` 名单的收进 `HITLRequest{action_requests, review_configs}`
3. `interrupt(hitl_request)` 暂停；恢复后按 decision 重建 tool_calls

**四个决策类型**（即流派2+3 的官方合体）：
| decision | 含义 | 实现 |
|---|---|---|
| `approve` | 批准执行 | 保留原 tool_call 放行 |
| `reject` | 拒绝 | 造 `ToolMessage(status="error")` 回喂模型，告诉它"别重试除非用户要求" |
| `edit` | 改参执行 | 替换 tool_call 的 name/args |
| `respond` | **人代工具回答（流派3）** | 造 `ToolMessage(status="success")` 跳过执行 |

**配置契约**：`interrupt_on={"bocha_search_tool": True}`（True=四决策全开）或 `{"coder_tool": {"allowed_decisions": ["approve","reject"], "description": ...}}`；名单外工具**自动放行**；支持 `when` 谓词按 args 内容决定拦不拦。接入点是 `create_agent(middleware=[mdw], checkpointer=...)`。

### 5.3 嵌套 supervisor 的关键实验：interrupt 冒泡机制（今天最值钱的验证）

工具源码已点名：`langgraph/prebuilt/tool_node.py:973` —— GraphInterrupt 是**特判异常，`except GraphBubbleUp: raise` 永远向上冒**，工具错误处理器吞不掉，明确含 "supervisor w/ tools" 场景。

**但实验推翻了一个"看起来合理"的实现**。用 InMemorySaver 搭主管 + 子代理（子代理编译成独立图、**配自己 saver + 自己 thread_id**、封装成 tool 给主管调），结果：

| 层 | 现象 | 危害 |
|---|---|---|
| 子代理 | interrupt 生效，自己挂起 | —— |
| 主管 | **完全无感**，`next=()` 正常收尾，把子代理半截返回当 ToolMessage 吃掉 | **静默错误**：主管以为干完了，子代理永久挂死等一个永远不会来的审批 |

**根因**：子代理带独立 checkpointer → 中断点落在子代理自己的 checkpoint，主管的图运行时看不到。"冒泡到主管"只在**共享同一 checkpoint 命名空间**时才成立。

**修正后验证通过（三条铁律）**：
1. **共享同一个 saver 实例**（主管和子代理 `compile(checkpointer=同一对象)`）——中断点落主管 checkpoint 的物理前提；
2. **工具内透传主管 config**：`from langgraph.config import get_config` → `await sub_graph.ainvoke(inp, get_config())`，不自己造 `{"thread_id":新id}`；
3. **resume 统一在主管层**：`astream(Command(resume={"decisions":[...]}), 同一thread_id)` → 决策**穿透工具调用边界**，直达子代理 `interrupt()` 那一行，子代理就地收到并续跑。

实验输出实证：中断时主管流出现 `__interrupt__` 事件（payload 带子代理内部 `{kind,what,who}`），`aget_state().interrupts[0].value` 有 `action_requests/review_configs`；resume 后完整走 `after_model→tools→model→收尾`。**tool-as-agent（PLAN 的 A 路线）不用退化真子图**，只要满足三铁律。

### 5.4 决策沉淀：为什么嵌套结构下要手搓而非迁 create_agent

- `create_agent` 只封装**单层 ReAct** 的 model↔tools 循环，middleware 只能挂在这两节点前后；
- 我的 PLAN 目标是 **supervisor（主管+子代理工具）+ 内层 HITL + 自定义节点链（画像注入/意图路由/RAG）**——middleware 表达不了节点链，也插不进子代理内层；
- **所以"手搓 gate"指的是自己搭多层图结构，但数据契约复用官方**（`interrupt_on`/`HITLRequest`/decision 语义），不重复造轮子。

### 5.5 遗留（HITL）
- [ ] 单图阶段先把 gate 落地：`agent_stream` 的 `__interrupt__` 在 `stream_mode="messages"` 里**是漏的**（实验只在 updates 模式显形）——最阴的坑，要想怎么保打字机效果又收到中断信号
- [ ] resume 形状统一：子代理中断处期望什么 resume 值，主管层就透传什么（官方 HITL 用 `{"decisions":[...]}`，手搓子代理可用裸值，两层契约必须一致）
- [ ] 共享 thread 的**历史串味**测试：连续调两个不同子代理，第二个启动时 messages 起点是否干净

## 六、午后讨论②：打包层——Tauri + React 前端

> 一句话：前端从"一个 agent_demo.html"升级成 React，桌面端用 Tauri 壳。关键认知是**两个 Rust 工件职责不同**（axum 网关在服务端 vs Tauri 壳在客户端），React 一次编写 Web/桌面共用，核心投资全在前端与 SSE 事件协议，Tauri 只是最后套上的薄壳。

### 6.1 架构决策

- **四层链路**：React SPA（Web 浏览器 / Tauri 壳共用）→ Rust axum 网关（服务端，管鉴权/限流/SSE 转发）→ FastAPI（auth/会话/LangGraph agent）→ PG+Redis。Tauri 壳与浏览器**平级**，都是网关下游。
- **桌面端形态一壳两用**：靠可配置 `base_url` 切换"远程模式（连部署网关）"与"本地模式（连本机 docker compose 起的 FastAPI）"——**不做真·自包含**（把 PG/Redis/FastAPI 塞进安装包 = 进程管理/端口/更新三座大山，留作后续演进）。
- **Tauri 壳要写的 Rust 极少**：开窗 + 注入后端地址/token + 以后要系统能力（存文件）才加 tauri command 桥。**别用 Rust 在壳里重写 HTTP/SSE 客户端**。
