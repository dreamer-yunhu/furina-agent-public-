## 一、核心架构决策(ADR)

| # | 决策 | 理由/依据 |
|---|---|---|
| 1 | **主管和子代理都是 `create_agent`,同一形态** | 区别只剩 `system_prompt` + `tools` 两张清单;主管的 tools = 子代理实例,子代理的 tools = 专属域工具。递归可拆 |
| 2 | **组合 + 依赖注入,不是类继承** | 子代理不"继承"主管任何东西;能力 = 主管显式注入什么。工具可见性一层层下放,coder 不注入就调不到 search |
| 3 | **主管 = 唯一持久记忆体**(checkpointer + store) | 官方三铁律:只给最外层图编译 checkpointer,子代理一律不传 → per-invocation。子代理配独立 checkpointer = 状态泄漏,不是隔离 |
| 4 | **子代理每次运行 = 白纸** | 子代理拿"任务简报" + 现场用工具取素材;干完即弃。隔离靠 as_tool 黑盒天然获得,不靠任何存储 |
| 5 | **上下文在派活时摊平打包**(self-contained task brief) | 主管把相关记忆提炼成任务简报注入 system_prompt/任务描述;子代理不需要自己回忆 |
| 6 | **子代理间永不直接通信,一切经主管中转** | 子代理 = 函数,返回值 = 它唯一对外说的话;coder 结果 → 主管 messages → 主管决定派给谁 |
| 7 | **反馈契约分两层** | 第一层(结果)走工具返回、主管能等到;第二层(interrupt/error)穿透主管直达最外层。判断口诀见 §五 |
| 8 | **coder 用 create_agent,主管将来也用 create_agent** | 与现 furina 手搓图(graph.py/state.py)是两代产物,不混用;将来 supervisor 用 create_agent 重写主管 |

### 心智模型总图

```
主管 = create_agent(持久工作台:checkpointer + store 记忆)
  │  派活时:把相关记忆摊平成任务简报,注入
  ▼
子代理 = create_agent(每单白纸:简报 + 现场取素材)   ← coder/comfyui...
  │  干完:只返回第一层契约结构(结果/错误)
  ▼
主管(拿结果 → 质量判断 → 验收 / 重做 / 派给下一个)
        ▲
        └─ 穿透一切:HITL interrupt / error 冒泡到最外层(第二层契约)
```

## 二、契约第一层:子代理 → 主管(任务结果)

走 as_tool 工具返回,主管能"等到"。**这是第一刀就要定死的结构**(子代理间传话唯一通道)。

```python
# 子代理作为工具的返回结构(结果契约)
class AgentResult(BaseModel):
    status: Literal["success", "error"]
    summary: str                    # 干了什么/结论 —— 主管质量判断依据
    error: AgentError | None        # status=="error" 时必填
    artifacts: list[str] | None     # 产出物路径/引用(可选)

class AgentError(BaseModel):
    kind: Literal["task_failed", "tool_failed", "timeout", "invalid_request"]
    detail: str
```

**边界约定**:
- `summary` 要"自包含、可被下一个子代理/主管直接理解",不含子代理内部噪音。
- `error` 不抛给主管当异常,而是**作为结构化返回**——主管决定:重试 / 换招 / 上报用户。
- 子代理内部的海量中间过程(tool 输出、报错堆栈)**不进 summary**,只进自身消息历史(干完即弃)。

## 三、契约第二层:冒泡事件(穿透主管 → 最外层)

主管"等不到"的、需要人或外层处理的东西走这层。复用 9.7 的 `type` 封闭事件集。

```python
# 事件封闭集(type 字段)——9.7 演进 + HITL 新增
type: "token" | "tool_start" | "tool_end"      # 常规流
    | "approval_required"                       # HITL:子代理内层中断,冒泡到最外层
    | "error" | "done"                          # 终态:错误以事件送达,不断流
```

**关键机制(官方姿势)**:
- 子代理内部 interrupt **穿透主管**,直达编译了 checkpointer 的最外层图,由人(UI)审批、再 `Command(resume)` 恢复。
- **主管对 HITL 是透明的**——它不是审批者。interrupt 不经过主管记忆、不经过子代理白纸,是架构里独立的一条线。
- 主管能"及时发现并处理"的边界 = **子代理返回之后**的质量判断(那 diff 不对→重做),靠又一次 model 调用,不是运行中实时打断。

## 四、记忆分层原则(主管管记忆,子代理白纸)

| 上下文类型 | 来源 | 谁持有 |
|---|---|---|
| 用户长期偏好/项目背景 | store / 主管 checkpointer | 主管,派活时提炼成任务简报 |
| 任务素材(要改的代码) | 文件系统 | 子代理现场 read_file/grep 取,**不算记忆** |
| 本次对话来龙去脉 | messages(checkpointer) | 主管 |

**反模式(已拍板否决)**:
- ❌ 子代理配独立 checkpointer → 跨任务"记住"上单 = 状态泄漏
- ❌ 共享 saver 实例给父子 → 官方三铁律第一条已否
- ❌ 子代理间直接共享全局状态传话 → 必须经主管

---

## 五、反馈契约判断口诀

> **主管能等到的走第一层(工具返回 / AgentResult);等不到、需要人或外层的走第二层(冒泡事件)。**

| 场景 | 走哪层 | 谁处理 |
|---|---|---|
| coder 干完,汇报结果 | 第一层 AgentResult | 主管(ReAct 再跑一轮做质量判断) |
| coder 干一半想改文件 | 第二层 approval_required | 最外层 UI + 人(HITL) |
| coder 崩溃/超时 | 第二层 error 终态 | 最外层(断流兜底) |

## 六、引擎形态规格(第一刀:coder)

```python
# create_agent API 用法(先用 API,再啃源码)——四动作:造/跑/看/验
graph = create_agent(
    model=llm,                       # 复用 app/agent/llm.py
    tools=[...],                     # 第一刀:只读工具族
    system_prompt="...",             # coder 开场白 / 任务简报注入点
    name="coder",                    # 将来被主管当子代理时的身份
    # 注意:不传 checkpointer → 天然白纸(隔离实证)
)
```

**第一刀验收三连**(冒烟脚本,backend 根下临时文件,跑完删):
1. 工具真被调用(updates 出现 tools 节点)
2. 它自己知道何时停(最终答复不再调工具)
3. 不传 thread_id 跑两次 = 白纸(无历史残留)

**工具分域**(PLAN §12:按域拆分,禁止全绑一个节点):
- 免审读族:`read_file` / `list_dir` / `grep` —— 第一刀
- shell 族:`CommandRunner` 抽象(bash/powershell 两实现,超时/沙盒 cwd/拦交互命令)—— 第二刀
- 写族:`apply_patch`(ApplyPatchOperation 强类型)—— 第三刀,此时才接 HITL 门闩

## 七、HITL 落点(第三刀,依据 9.8 调研)

- `HumanInTheLoopMiddleware` 只能挂 create_agent 编译的 runtime → **coder 选 create_agent,第三刀是复用官方而非自造轮子**(关键收益)。
- 审批对象 = `{path, diff}` 而非工具名(OpenAI ApplyPatch 派)。
- 拒绝对称回喂 LLM,走历史通道(铁共识 1)。
- interrupt 挂起期间新消息到达 → 作废 pending(铁共识 3)。
- 铁律:interrupt 不包 try/except;resume 后节点从头重跑 → gate 前不得有副作用。
