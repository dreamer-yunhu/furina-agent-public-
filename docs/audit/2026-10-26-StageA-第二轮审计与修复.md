## 2. 缺陷清单

### D1（重要，静默）`intent_error` 跨轮污染新一轮的意图提示词

- 位置：`agent/nodes/supervisor.py:71-77`（读 `state.intent_error` 回填）、`99-107`（重试耗尽出口不清它）
- 复现：同 thread，第一轮意图格式错误用满 2 次重试 → 第二轮虽然成功，但**第一次**分类调用收到的消息里已带上
  「上一次输出不合法（不是合法 JSON（Expecting value））」—— 一条凭空出现的前置失败前提。
- 根因：`intent_error` 只在**校验成功**出口被清；失败出口原样保留。

### D2（重要，状态矛盾）失败轮保留上一轮 `result`

- 位置：`nodes/supervisor.py:127-133`（`route_failed_node` 只写 `route_status`）
- 复现：第一轮 CHAT 成功（`result="你好呀"`）→ 第二轮意图失败 →
  `route_status=failed` 且 `result="你好呀"` 同时存在。
- 影响面：`stream._stream_graph` 只读 `route_status`/`route_error`，SSE 不受影响；
  但 checkpoint 里是一个自相矛盾的状态，未来的历史恢复/结果面板会读到错配数据。

### D3（次要）`subagent_task` 在 CHAT 轮残留

- 位置：`nodes/supervisor.py:120-123`（只对 CODE 赋值）
- 复现：CODE 成功 → CHAT 成功，`subagent_task` 仍是上一轮的 CODE 任务文本。
- 影响面：唯一消费者 `nodes/coder.py:43` 只在 CODE 轮读，且下个 CODE 轮会覆写 → 今天无功能影响。

### D4（结构）重置职责散落在调用方，且只覆盖 1 个字段

- `stream.py` / `tests/_t23_testkit.py` / `smoke_coder_isolation.py` 三处各写一遍 `intent_attempts: 0`；
  `smoke_supervisor_route.run_case` 干脆没写（靠"每个用例换新 thread"侥幸成立）。
- 这正是 D1~D3 的土壤：**"按 run 重置"只做了一半**。

### D5（次要）空 `user_input` 会先建任务再失败

- `api/contracts.py` 的 `AgentRequest.user_input` 只有 `max_length`；
  `supervisor.intent_node` 对空输入 `raise ValueError`（视为编程错误）。
- 结果：客户端传 `""` → 建好 Task/Execution → `graph_error`，留一条必然失败的任务记录。

### D6（测试基建）忘装意图替身 = 静默连网

- 历史事故：`smoke_t23_decision_api` 首次失败（`StopIteration`），真因是没装替身 → 走真模型 → 路由失败 → 等不到中断。
- 现状：每个图级测试各自手动 `install_intent(...)`，没有兜底。

### D7（文档漂移）

- 实施报告写「状态：**未提交**」，实际已在 `a6892d2` 提交。
- 意图契约表把 `reason` 写成输出格式的一部分，但代码从不校验它（详见 §4）。

## 3. 修复

### 3.1 结构性修复：`begin_turn_node`（D1~D4）

新增 `agent/nodes/supervisor.py::begin_turn_node`，接到 `START` 之后：

```
START ─▶ begin_turn_node ─▶ intent_node ─▶ validate_intent_node ─┬─ CHAT ─▶ chat_graph ─▶ END
                  ▲                    ▲                          ├─ CODE ─▶ coder_graph ─▶ END
                  │                    └── Command(goto="intent_node") 重试（绕开 begin_turn）
                  └── 每个 run 从 START 进来都会经过一次
```

它把 **run 级字段**一次性重置为 `None`（`intent_attempts` 为 `0`）：
`intent / intent_raw / intent_error / route_status / route_error / result / subagent_task`。

**不清** `messages` / `task_input` / `task_id` / `execution_id`。

为什么这样不会破坏别的路径：

| 路径 | 是否经过 `begin_turn_node` | 语义 |
|---|---|---|
| 新的 `POST /agent` run | 是 | 新一轮开始，重置正确 |
| 意图校验失败重试 | 否（`Command(goto="intent_node")`） | 同一轮内保留 `intent_error`，回填反馈照旧 |
| `Command(resume=...)` 审批恢复 | 否（从断点继续） | 不重置，恢复现场不变 |

配套**删除**三处调用方的 `intent_attempts: 0`（`stream.agent_stream`、`_t23_testkit.run_input`、
`smoke_coder_isolation.run`），入口回到"只提供权威输入"的单一职责。

### 3.2 D5：HTTP 层拦截空输入

`api/contracts.py::AgentRequest`：`user_input` 加 `min_length=1` + `_strip_and_reject_blank`
（首尾空白剥掉；只剩空白 → 422）。实测：`""` → `string_too_short`；`"   "` → `value_error`；`" hi "` → `"hi"`。

`supervisor.intent_node` 里的 `ValueError` **保留**作最后一道断言（它挡的是"调用方绕过 HTTP"的编程错误）。

### 3.3 D6：测试替身 fail-fast

`tests/_t23_testkit.py` 在**导入时**把 `supervisor.intent_llm` 换成 `_IntentNotInstalled`，
它的 `ainvoke` 直接抛 `RuntimeError("测试未安装意图替身…")`。
用例开头调用 `install_intent(...)` 会覆盖它，行为不变；忘了装则**立刻报错**而不是静默连网。

### 3.4 D7：文档

- 实施报告头部状态改为"已提交 `a6892d2`"。
- 意图契约见下节（`reason` 明确为**可选**，不参与校验）。

## 4. 意图输出契约：`reason` 的定位（拍板记录）

**结论：`reason` 不是必填契约，但要有落点 —— 已按用户拍板加占位字段 `intent_reason`。**

### 4.1 为什么不是必填

- 依据：`_parse_intent` 只校验 `intent`；全链路无消费者。
- 22 例边界实测：缺 `reason`、`reason` 类型错（`123`）均被**静默接受**；多余字段允许；
  `"chat"` / `"  CODE  "` 经 `strip().upper()` 归一化后通过；` ```JSON `（大写）与 BOM 前缀会判格式错误并重试。
- 为什么不设为必填：模型偶尔漏一个装饰字段是常态，设成 `format_error` 会白白吃掉一次重试预算，
  而路由结论本身完全正确。

### 4.2 占位字段的规则（已实现，2026-10-26 拍板）

| 情形 | 行为 |
|---|---|
| `reason` 是字符串 | `strip()` 后写入 `SupervisorState.intent_reason` |
| 缺失 / 空串 / 类型不对 | 写 `None`，**不影响路由、不消耗重试** |
| 超过 255 字符 | 解析处截断到 255（与 state 的 `max_length` 对齐，避免撞 Pydantic 校验把图打崩） |
| 意图不受支持 | `reason` 照样留档 —— 路由失败时"模型为什么这么选"是最有用的线索 |
| 轮次边界 | 属于 run 级字段，由 `begin_turn_node` 清空 |

实现要点：
- `_parse_intent` 返回值从 3 元组改成具名 `ParsedIntent(intent, reason, format_error, unsupported)`
  —— 相邻两个"错误原因"用位置传参太容易写反，具名更可靠。
- `_clean_reason()` 是纯函数，**永不抛异常**：`reason` 再离谱也只能变成 `None`。

### 4.2b 消费者（2026-10-26 接入，避免僵尸字段）

| 场景 | 消费者 | 效果 |
|---|---|---|
| 路由失败（不支持意图 / 重试耗尽） | `_with_reason()` 把 reason 拼进 `route_error` | 用户看到的 SSE `error.message` 变成：`意图 'RAG' 不在当前版本支持范围 ['CHAT','CODE']（模型理由：查资料）` |
| 路由成功 | `validate_intent_node` 的 `logger.info` | 日志里一行 `意图路由 intent=CODE reason=要改文件` —— checkpoint 里的 `intent_raw` 没人会去翻 SQLite |
| 判断依据 | **没有** | 任何分支都不读它。它只解释"为什么"，不决定"去哪" |

> 刻意没做：写进 Task 元数据。节点里出现 session 就破坏了 D-SUP-06 的分层
> （`route_failed_node` docstring 有同样的约束）；要落库应走 runtime，属于下一阶段。

### 4.3 已知容错边界（暂不修，未在真实链路观察到）

fence 只认小写 `json`；BOM 前缀判非法。
