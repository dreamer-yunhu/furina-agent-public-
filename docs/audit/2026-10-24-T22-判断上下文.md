## 0. 一句话

T22 要回答：**一条已批准的拆求，在什么条件下允许把 Task/Execution 从“等待/挂起”带回运行，并让图 resume；不满足时如何明确拒绝。**

它同时管两件事：**恢复前校验**（持久化状态是否可信）与**恢复动作**（迁移 + 图恢复）。

## 2. T22 应该长什么样（提案）

```
用户提交决定（T20 已落库）
        │
        ▼
[恢复前校验]  ── 读 DB：approval / execution / task / 同批其它审批 / 目标文件
        │
        ├─ 不通过 → ResumeOutcome（明确原因），状态不变
        │
        ▼
[条件迁移]  Task/Execution → RUNNING（T19 CAS，成对）
        │
        ▼
[图恢复]  Command(resume=...)（桌面层）
```

**关键边界**：数据库迁移与图 resume 不可能是一个事务；校验必须在迁移*之前*，图恢复在迁移*之后*。

## 4. 需要你拍板的问题

### Q1 · T22 的范围：只校验，还是校验 + 迁移？

| 选项 | 做什么 | 后果 |
|---|---|---|
| A | 只做校验，返回 `ResumeOutcome`；调用方自己迁移 | 职责最纯；但“校验通过→迁移”之间的窗口由调用方承担 |
| **B（推荐）** | 校验 + 通过后**成对迁移到 `RUNNING`**；图 resume 留在桌面层 | DB 内原子；与 T19/T20 分层一致 |
| C | 校验 + 迁移 + 直接 resume 图 | core 依赖 LangGraph，分层被打破 |

### Q2 · 允许从哪些状态恢复？

| 选项 | 允许 | 后果 |
|---|---|---|
| **A（推荐）** | `WAITING_APPROVAL` 与 `SUSPENDED` 都允许 | 正常批准走前者，迟到批准走后者 |
| B | 只允许 `SUSPENDED` | 正常批准路径无法恢复，必须等超时，不合理 |
| C | 只允许 `WAITING_APPROVAL` | 迟到批准永远无法恢复 |

### Q3 · 批内仍有未决审批时怎么办？

| 选项 | 行为 | 后果 |

| B | 只恢复已批准的那一条 | 执行会带着未决操作继续跑，越权 |

## 5. 推荐的最小范围（若 Q1=B）

新增 `packages/core/src/furina_core/task/resume_service.py`：

```python
class ResumeOutcome(str, Enum):
    RESUMED
    NOT_FOUND
    SCOPE_MISMATCH
    NOT_APPROVED
    PENDING_APPROVALS
    ILLEGAL_STATE
    ALREADY_EXECUTED
    OLD_HASH_MISMATCH

@dataclass(frozen=True)
class ResumeResult:
    outcome: ResumeOutcome
    failure_code: ValidationFailureCode | None = None
    task: AgentTask | None = None
    execution: AgentExecution | None = None

async def validate_and_resume(session, *, task_id, execution_id, now=None) -> ResumeResult
```

流程：

1. 读 task/execution → 不存在 `NOT_FOUND`
2. 终态 → `ILLEGAL_STATE`
3. 状态不在 `WAITING_APPROVAL / SUSPENDED` → `ILLEGAL_STATE`
4. 该 execution 下仍有 `PENDING` 审批 → `PENDING_APPROVALS`
5. 该 execution 的审批是否全部 `APPROVED`；有 `REJECTED/REVOKED` → `NOT_APPROVED`
6. 任一 `tool_execution_status != NOT_STARTED` → `ALREADY_EXECUTED`
7. 写类工具的 `old_hash` 与文件现状不符 → `OLD_HASH_MISMATCH`
8. `transition_pair(WAITING_APPROVAL/SUSPENDED → RUNNING)`；仅 APPLIED 算 `RESUMED`

**不做**：不改审批状态、不执行工具、不建新 Task、不 resume 图。

## 6. 测试矩阵（预告）

1. `SUSPENDED + APPROVED` → RESUMED，两表变 RUNNING
2. `WAITING_APPROVAL + APPROVED` → RESUMED
3. 审批仍 PENDING → PENDING_APPROVALS，状态不变
4. 审批 REJECTED → NOT_APPROVED
5. 终态任务 → ILLEGAL_STATE
6. 同批还有 PENDING → PENDING_APPROVALS
7. 已执行（`tool_execution_status=SUCCEEDED`）→ ALREADY_EXECUTED
8. `old_hash` 不符 → OLD_HASH_MISMATCH
9. 两独立 Session 并发恢复 → 只一个 RESUMED
10. 迟到批准恢复成功（不因 deadline 拒绝）
11. T18/T19/T20/T21 回归
