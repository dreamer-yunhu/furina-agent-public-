## 四、T19 `transition_pair` 真实语义

- 签名：`transition_pair(session, *, task_id, execution_id, task_from, task_to, execution_from, execution_to)`（`lifecycle_service.py:99`）
- 支持 `WAITING_APPROVAL → RUNNING`、`SUSPENDED → RUNNING`（Task 与 Execution 的迁移表均有）
- 内部 `session.begin()`，**要求传入未开启事务的 Session**
- 两次迁移均走 CAS（`repository.transition_task/execution`，`commit=False`）
- 任一侧未生效 → `_PairAborted` → 整体回滚 → 返回 `(CONFLICT, CONFLICT)`
- 返回 `(TransitionOutcome, TransitionOutcome)`；只有 `(APPLIED, APPLIED)` 表示成功
- 回滚行为已被测试验证（`smoke_lifecycle.py` 失败注入）

## 九、结论

1. T18–T21 的**服务层**已具备 T22 所需的基础；但**全部没有端到端接线**。
2. T22 可以做、可以测，但 C7/C9 只能在 T23 后完整验证；C8 依赖 T23 写入 DB 的 `old_hash`。
3. **新增关键风险**：数据库迁移到 RUNNING 与图恢复不是同一事务，恢复失败后的补偿路径在设计上必须明确。
