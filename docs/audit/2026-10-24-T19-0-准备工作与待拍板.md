## 二、状态机提案（需逐条拍板）

### 2.1 Task

| From | 允许的 To | 触发者 | 备注 |
|---|---|---|---|
| `QUEUED` | `RUNNING` / `CANCELLED` | 主管认领 / 用户取消 | |
| `RUNNING` | `WAITING_APPROVAL` / `COMPLETED` / `FAILED` / `CANCELLED` | 出现待审 / 正常结束 / 失败 / 取消 | |
| `WAITING_APPROVAL` | `RUNNING` / `SUSPENDED` / `CANCELLED` | 决定完成 / 超时 / 取消 | 超时**不**改审批状态 |
| `SUSPENDED` | `RUNNING` / `FAILED` / `CANCELLED` | 迟到决定且校验通过 / 判定不可恢复 / 取消 | |
| 终态 | — | — | `COMPLETED` / `FAILED` / `CANCELLED` 不可出 |

**待确认**：
- 是否需要 `RUNNING → QUEUED` 回退？**建议不允许**（会破坏审计时序）。
- `SUSPENDED → FAILED` 只能由显式操作触发，**不得由超时自动触发**（规范 §4）。

### 2.2 Execution

| From | 允许的 To | 备注 |
|---|---|---|
| `CREATED` | `RUNNING` / `CANCELLED` | |
| `RUNNING` | `WAITING_APPROVAL` / `COMPLETED` / `FAILED` / `VALIDATION_FAILED` / `CANCELLED` | |
| `WAITING_APPROVAL` | `RUNNING` / `SUSPENDED` / `CANCELLED` | |
| `SUSPENDED` | `RUNNING` / `FAILED` / `CANCELLED` | 迟到决定恢复 |
| 终态 | — | `VALIDATION_FAILED` / `COMPLETED` / `FAILED` / `CANCELLED` |

**待确认**：
- `VALIDATION_FAILED` 是终态，重委派**新建 Execution**，不复活旧的（建议保持）。
- `SUSPENDED → RUNNING` 在 T19 只做迁移原语；**是否允许迁移由 T22 的恢复前校验决定**，两者不要混。

## 三、事务边界（T19 的真正难点）

现实场景：审批完成后需要 `Execution: WAITING_APPROVAL → RUNNING` **且** `Task: WAITING_APPROVAL → RUNNING`，两者必须同成同败。

但 repository 每个方法都自己 `commit()`（F8），所以现在做不到。

| 选项 | 做法 | 代价 |
|---|---|---|
| **A（推荐）** | repository 的迁移函数加 `commit: bool = True` 参数 | 改已测函数签名，但默认值兼容；改动最小 |
| B | 在 service 里复制一份 SQL | 违背“只做有调用者的修改”，两处漂移 |
| C | 引入 UnitOfWork / 事务上下文管理器 | 抽象最重，当前只有一个调用场景，过度设计 |

> 需要拍板：**Q-T19-3**。

## 四、迁移结果语义

现在 `transition_*` 只返回 `bool`，调用方无法区分：

- 失败因为**当前状态已经是目标状态**（幂等重复调用）
- 失败因为**迁移非法**
- 失败因为**并发被抢**

建议返回一个小结果对象：

```text
TransitionResult(applied: bool, from_status, to_status, reason: "APPLIED" | "ILLEGAL" | "CONFLICT" | "NOOP")
```

或者保持 `bool` + 新增纯函数 `is_legal_transition(from, to) -> bool`，调用方先判断再迁移。

> 需要拍板：**Q-T19-4**。

## 五、失败与重委派

- `Task FAILED` 后由主管新建子 Task：`parent_task_id` + `redelegation_key`（UNIQUE）。
- `redelegation_key` 需要稳定公式，建议：`sha256(f"{parent_task_id}:{ValidationFailureCode}")`。
- `ValidationFailureCode` 目前无人消费（F5），T19/T22 才会接。

> 需要拍板：**Q-T19-6**。

## 六、测试计划（T19 实施时编写）

1. **合法矩阵**：表中每一条允许的 `from → to` 都能成功
2. **非法矩阵**：每一条不允许的组合被拒绝，且状态不变
3. **终态不可迁移**
4. **并发**：两个协程同时做同一 `from → to`，只有一方成功
5. **联动原子性**：Task 迁移成功、Execution 迁移注入异常 → 两者都回滚（依赖 Q-T19-3）
6. **重复失败重委派**：同一 `redelegation_key` 只建一个子 Task
7. **时间字段**：`finished_at` 仅在终态写入；`Execution` 是否补 `updated_at`（Q-T19-5）
