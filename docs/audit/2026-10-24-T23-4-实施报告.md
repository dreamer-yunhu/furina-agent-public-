## 三、实现结果

### 3.1 T22 批次范围

`validate_and_resume(..., approval_ids=[...])`：

- 只校验传入的审批 id；
- 任一 id 不属于该 Execution → `NOT_FOUND`；
- 不传 `approval_ids` 时保持旧行为（校验整个 Execution）。

这解决了“同一 Execution 第二批审批被第一批已执行阻断”的问题。

### 3.2 T22 拒绝模式

`allow_rejected=True`：

- 无 PENDING；
- 无任何工具已开始（全部 `NOT_STARTED`）；
- 至少一条 `REJECTED`；
- 允许同批存在 `APPROVED + NOT_STARTED`；
- `REVOKED` 仍视为不可恢复。

拒绝恢复成功后 Task/Execution 成对迁到 `RUNNING`，由图走拒绝分支；不执行工具。

### 3.3 恢复前双向预检

`AgentRuntime.preflight_resume`：

1. 读取 `graph.aget_state(config, subgraphs=True)`；
2. 读不到 → `checkpoint_unavailable`；
3. 无 interrupt → `state_mismatch`；
4. 汇总 interrupt 里的 `approval_id` / `tool_call_id`；
5. 与数据库审批行做精确集合比较；
6. 从子图 `coder_messages` 取工具调用参数，重算 `args_hash`；
7. 不一致 → `args_mismatch` / `state_mismatch`；
8. 返回当前批次 `approval_id` 列表供 T22 使用。

预检失败**不改变任何数据库状态**。

### 3.4 恢复顺序

`/agent/resume`：

1. 归属校验；
2. 活动 Execution 定位图键；
3. 决定与待审 `tool_call_id` 对齐；
4. T20 持久化决定；
5. 双向预检；
6. T22 校验 + T19 成对迁移到 `RUNNING`；
7. 以上全部通过才恢复图。

任一前置失败 → 404/409/503，不调用图。

### 3.5 工具执行保护

- 全批准时 `handle_review_fn` 写入 `approved_approvals`（`approval_id ↔ tool_call_id`）。
- `guarded_tools_node`：
  1. 整批 `claim_batch`；任一失败 → 整批不执行；
  2. 调用原 `ToolNode`；
  3. 按 `ToolMessage.status` 映射 `SUCCEEDED/FAILED/UNKNOWN`；
  4. 写回审批行。
- 工具异常时全部记 `UNKNOWN`，不自动重放。
- 安全工具批次没有 `approved_approvals`，直接透传，行为不变。

### 3.6 恢复失败补偿

`handle_resume_failure`：

- 当前状态对不是 `RUNNING` → 不改；
- 该 Execution 下全部审批 `NOT_STARTED` → `suspend_after_resume_failure` → `SUSPENDED`（可重试）；
- 任一审批已开始/结果未知 → Task/Execution → `FAILED`，审批执行状态保留，禁止自动重放。

新增关键断言：

1. 旧批已执行时，无范围 → `ALREADY_EXECUTED`；指定新批范围 → `RESUMED`。
2. 不存在的审批 id → `NOT_FOUND`，状态不变。
3. `REJECTED + APPROVED` 同批，拒绝模式 → `RESUMED`。
4. 拒绝模式没有 REJECTED → `NOT_APPROVED`。
5. `UNKNOWN` → `ALREADY_EXECUTED`，禁止重放。
6. 整批认领第一次成功、第二次失败。
7. 恢复失败且未开始 → `SUSPENDED`。
8. 恢复失败且已开始 → `FAILED`，审批保持 `RUNNING`。
9. 同一 Execution 两批审批：第一批 `SUCCEEDED` 不阻断第二批。
10. 参数快照被篡改 → 409 `args_mismatch`，工具未执行。
11. 删除 checkpoint → 409 `state_mismatch`。
12. 拒绝后恢复：文件未写、审批 `REJECTED`、运行正常结束。
