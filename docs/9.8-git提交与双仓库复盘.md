## 二、核心心智模型:git 的"四层 + 两套记录"

git 操作每层独立,**想清楚动哪层再动手**,就不会翻车。

| 层 | 是什么 | 相关命令 |
|---|---|---|
| 磁盘文件 | 你真正看到/编辑的文件 | 无(git 不主动动它) |
| 索引(index/staging) | "下一提交包含谁"的清单 | `git add` / `git rm --cached` |
| 提交历史 | 不可变的快照链 | `git commit` |
| 分支 | 指向某条提交的指针 | `git branch` / `checkout` |
| remote | "我往哪推"的地址标签 | `git remote add` |

### 两个"删除"必须分清(本次核心收获)

| 命令 | 删除什么 | 磁盘文件 |
|---|---|---|
| `git rm -r <dir>` | 跟踪 + 磁盘文件 | ❌ 真删(历史可救) |
| `git rm -r --cached <dir>` | 只删跟踪记录 | ✅ 原样保留 |
| `.gitignore` 加规则 | 什么都不删 | ✅ 只挡未来未跟踪文件的误 add |

**口诀**:`--cached` 只动索引;`.gitignore` 只挡未来;真正的物理删除是 `git rm`(不带 --cached)。防手抖 = `--cached` + `.gitignore` 双保险 + 历史兜底,三层。

## 三、孤儿分支构造干净公开版(复盘全流程)

```bash
# 1. 开一条"没有父母"的新历史线(index 残留旧树 86 文件,含 knowledge)
git checkout --orphan public-clean
# 2. 清空索引(旧跟踪全解除,磁盘文件不动)→ 全部变 untracked
git rm -r --cached . -f
# 3. 白名单重构(只 add 想公开的,从源头杜绝误纳)
git add .gitignore backend/app backend/run.py pyproject.toml uv.lock frontend
# 4. 校验 staged 清单:grep 污染项(knowledge/node_modules/log/docs)全 0
git diff --cached --name-only
# 5. 提交成新历史第一条
git commit
# 6. 双 remote + 推送(本地分支名 ≠ 远程分支名)
git remote add public https://github.com/dreamer-yunhu/furina-agent-public-.git
git push public public-clean:main
# 7. 推送后从远端拉取校验(数文件 / grep 污染项)
git fetch public main && git ls-tree -r --name-only FETCH_HEAD | wc -l
```

### 踩过的坑(务必记住)

**坑① 孤儿分支共享工作区**。orphan 分支和原分支用同一个工作区,`git checkout` 切换时 git 会用该分支版本**重写工作区文件**。若在孤儿分支 commit 了原分支的"未提交修改",切回时那些改动会被旧版本覆盖(改动没丢,在孤儿分支提交里)。

**恢复手法**:
```bash
git checkout master
git checkout public-clean -- <file>   # 把孤儿分支里的最新内容搬回工作区
git reset HEAD -- <file>              # 取消暂存,回到"已修改未暂存"正常态
```

**坑② knowledge 浸在历史里,不是只在工作区**。公开仓库一旦推送,历史被缓存/fork,无法真删。所以"不 add knowledge"拦不住历史里的它,必须孤儿分支从历史层面隔离。

## 六、PyCharm 提交防误操作指南

### 你的真实风险点
master 工作区目前有一堆 **untracked** 文件(docs/ 学习记录、frontend/ 等)。PyCharm 提交最容易翻车的场景:**想把某个文件提交,结果把整个 Changes 列表全提交了**。

### 提交面板规则(先懂再点)

PyCharm 提交面板(`Commit` 工具窗口 / `Ctrl+K`)把文件分两类:
- **Changes / 默认变更**:已跟踪文件的修改,**默认全勾选**
- **Unversioned Files / 未版本控制**:untracked 新文件,**默认不勾**,且列表折叠在底部

**你的误提交事故只会来自"Changes 全勾了 + 没看 diff 就 Commit"**。

### 安全提交五步

1. **只勾想提交的文件**:在 Changes 列表里,把这次无关的文件**取消勾选**(比如只想提 graph.py,就只留它)。别用顶部 "Commit All"(有的版本显示为全选按钮)。
2. **逐个点文件看右侧 diff**:提交面板下方是 diff 预览,确认没有 `.env`、密码、knowledge、docs 误入。
3. **确认后点 "Commit..."(不带 Push)**。除非确定要上线,否则**别点 "Commit and Push..."**。
4. 提交完立刻看 `Git → Log`,确认最新提交里只有你想要的。
5. **发现提交错了、还没 push** → `Git → Uncommit Commit`(等价 `git reset --soft HEAD~1`,改动回到暂存区,可重新整理)。

### 让"危险文件"根本不出现(治本)
- **knowledge**、**docs 学习记录**、**.env** 这些不想让它出现在提交面板的文件,右键 → `Git → Add to .gitignore`。加进 .gitignore 后,它们**永远不出现在 Changes/Unversioned 列表**,从源头杜绝误勾。这是最省心的做法。
- 只对"暂时不想提交、以后要提交"的文件用**手动勾选/取消勾选**;对"永远不该提交"的用 .gitignore。

### 我这次帮你做的与 PyCharm 的对应
- `git rm --cached` 移出跟踪 = PyCharm 里右键文件 → `Git → Remove...`(勾选 "Delete local file" 与否)或命令行。**注意 PyCharm 的 Remove 默认会问是否删磁盘文件——务必选"不删"或看清楚选项**。
- 提交面板看不到的东西 = 已 .gitignore 的(知识语料、*.log)。

## 八、实战复盘:PyCharm 签出造出重复 main 分支(2026-09-08 晚)

### 事故还原
- 场景:在 PyCharm 切分支时,误签出了远程 public/main 的**本地跟踪分支 main**(而非本地 public-clean)。
- **PyCharm 对远程分支签出 = 自动新建同名本地分支并绑定该远程**。于是本地凭空多了个 `main`,`git branch -vv` 显示它 `[public/main]`——push 目标天然是 public。
- 在上面改了几行空行、commit(两笔 "测试")、push → 目标 public。**内容无害(空行),但暴露了机制:分支推送目标不由名字决定,由"跟踪谁"决定。**
- 附带:切分支时 PyCharm 弹窗问"变基 / 丢弃本地"——选了变基(rebase),**安全**(不丢改动,只是重放到远程之上)。

### 结论与铁律
1. **推送目标 = 分支跟踪的远程(`git branch -vv` 方括号里的东西),不是分支名。** master→私有;只有 public-clean→公开。
2. **公开轨道只认 public-clean 一个名字**,见到其它指向同点的重复分支(main 之类)一律删,避免混淆再选错。
3. **遇到 PyCharm 弹窗选 rebase/丢弃 → 永远选"变基/rebase",绝不选"丢弃/discard/force checkout"**(后者删本地改动)。
4. 处理:两笔 "测试" 提交用 `git reset --mixed HEAD~2` 回退(改动退回工作区,不丢);`git branch -D main` 删除重复分支(先确认三处 rev-parse 同点再删)。

### 当前最终拓扑(干净态)
```
* master        [origin/master]     → 私有 furina-agent(日常开发)
  public-clean  [public/main]       → 公开 furina-agent-public-(唯一公开轨道)
(本地 main 已删,远端 public/main 未被污染,仍在 f6c902c)
```

### 日后防错判断链(每次 push 前默背)
```
1. git branch -vv → 我当前分支跟踪谁?[origin/master]=私有 / [public/main]=公开
2. 想推私有 → 必须在 master;想推公开 → 必须在 public-clean
3. 遇到弹窗 → 永远选变基(Rebase),不选丢弃(Discard/Force)
```
